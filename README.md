# SwEasy

基于 MaaFramework 的《魔灵召唤》自动化项目。

## 下载与发布

桌面前端使用 MXU。GitHub Actions 在推送 `v*` 标签后自动创建 Release，提供：

- Windows x64：`SwEasy-win-x64-v版本.zip`，解压后运行 `mxu.exe`；需要 Windows WebView2 Runtime。
- Linux amd64：`SwEasy-linux-amd64-v版本.tar.gz`，解压后运行 `./mxu`。
- Linux 安装包：`.deb`、`.rpm`、`.pkg.tar.zst`（pacman），安装后从应用菜单或 `sweasy` 命令启动。

包内包含 MaaFramework、独立 Python 3.12、Python Agent、OCR、网页编辑器和规则 SQLite，无需另外安装 Python。
Linux 构建要求 glibc 2.39+（例如 Ubuntu 24.04+ 或相应较新发行版），以及 WebKitGTK 4.1、AppIndicator、librsvg、libusb 和 ADB；安装包声明对应依赖，便携包需自行安装。
Linux 安装包的只读程序位于 `/opt/sweasy`，启动器同步到 `${XDG_DATA_HOME:-~/.local/share}/sweasy` 后运行；升级保留该目录中的 `config/` 和 `debug/`，卸载软件包不会删除个人数据。

仓库中的 `assets/rune-filter.rules.sqlite3` 只保存规则，不包含导入的账号 JSON；首次启动会导入规则，已有用户规则不会被覆盖。
本地 `config/`、账号导出 `forodo-*.json` / `account-*.json` 和网页运行信息均被 Git 忽略，也不进入发布包。
需要发布新的本地规则时运行 `python tools/export_rules.py`，它从 SQLite 提取规则到全新数据库，而不是复制含账号数据的原数据库；随后提交生成的规则库。

发布命令：`git tag v0.1.0`、`git push origin main`、`git push origin v0.1.0`。普通提交与手动运行只构建 Actions artifacts，不创建 Release。
上游版本固定在 `.github/workflows/install.yml`，MXU 的 AGPL、MaaFramework 的 LGPL 和 Python 许可随包保留；项目代码仍使用 MIT。

## 当前功能

- 启动国服中文客户端并进入庭院。
- 处理已采集的 Hive、商店和收件箱弹窗。
- 在庭院默认视野内识别带动画的连续战斗建筑。
- 点击建筑并打开连续战斗地区选择页。
- 配置并选择卡伊洛斯地下城种类与层数。
- 配置并选择次元洞口区域与难度阶段。

当前版本会完成副本选择并停在队伍配置页，不会开始战斗、购买资源或消耗能量。

## 符文仓库筛选

当前版本已支持从 `5559` MuMu 模拟器的游戏内 `魔灵保管所 -> 符文 -> 管理` 页面扫描未装备符文：

- `启动/重启符文筛选网页`：通过 Agent 自定义动作启动并捕获启动器输出，等待服务健康检查通过后，在与符文扫描相同的可见任务日志中打印实际访问地址。没有返回地址或启动器报错时任务会失败，不再把“只创建了命令进程”误报成启动成功。服务不会自动打开浏览器；旧服务无法终止（例如由管理员权限启动）时会改用 `8766` 起的空闲端口。规则和最近导入的账号 JSON 保存到本地 SQLite `config/rune-filter.sqlite3`；网页启动后也可以使用顶部“重启网页服务”按钮。
- `预览仓库筛选结果`：扫描并输出保留/出售判定，不会点击出售。
- `仓库符文自动出售`：仅对规则明确判定为 `SELL` 且详情识别完整的符文执行出售。

自动出售流程会对当前候选按 `+6 -> +9 -> +12` 分阶段强化，`+0/+3` 符文都从 `+6` 起步。潜力判断仍按每 3 级一次副属性变化进行推演；每次实际强化后重新 OCR 详情并计算规则，只有仍存在达到保留规则的可能性才会继续，确定无法达标时才出售。强化按钮、确认按钮、等级变化或详情识别不完整时会停止任务，不会盲点。预览任务不会实际强化，只统计“建议继续强化”的数量。

稀有（蓝色）符文命中最高优先级的立即出售规则，不进行强化路径搜索，也不会尝试强化；已装备、已锁定或识别不完整的符文仍由保护逻辑优先保留。

强化前日志会列出剩余强化节点、搜索状态数，以及最多 3 条按单次最高值推演的可达保留路径；每次强化后重新打印。决定出售时会说明是命中出售规则，还是剩余所有合法强化分配均无法达标，并列出最多 3 个最接近的保留规则及尚未满足的具体条件。数值缺口同时显示“当前值 / +12 最佳值”，并注明哪些节点可以强化该属性、哪些节点必须新增副属性；例如英雄 +6 只有 3 条普通副属性时，+9 可继续强化，+12 必须揭示第 4 条副属性，先天属性不占该名额。

仓库网格按紧密排列处理：确认详情弹窗未打开且同一格重试后仍为空时，视为当前可见区域已经到末尾，立即停止点击后续格子并执行三行翻页。连续两个翻页视图都没有扫描到新符文时结束，避免在仓库末尾反复空翻。

用途规则中的“构筑属性”同时计算主属性和副属性，并按满级主属性评估潜力；单条速度和单条极品副属性仍只看真实副属性。规则引擎会自动处理 1 号位不出防御/防御%、3 号位不出攻击/攻击%的限制，强化预估也不会等待这些不可能出现的属性。

效率日志保留与 SWEX Rune Card 一致的原始四项数值，并额外显示规则实际使用的“实用效率”。所有规则中的效率字段统一使用实用效率：固定体力、固定攻击、固定防御副属性及其磨炼潜力按 50% 计入，速度不减半，百分比、暴击、爆伤、命中和抵抗保持 100%；1/3/5 号位不可避免的固定主属性不受惩罚。

猛攻二/四/六号位如果是体力、防御、命中或抵抗主属性，会由高优先级错配规则直接出售，速度副属性不再让它进入强化流程；迅速及体防套装的错配规则仍保留原有速度例外。

猛攻、激怒、刀刃的六号位命中/抵抗主属性采用更严格的专用流程：没有速度副属性立即出售；有速度时只允许追未磨炼速度 21，所有剩余强化节点都必须落在速度上。实际分阶段强化后会比较速度增量，只要任一节点偏离速度就立即出售，不允许其他输出或高效率规则兜底；宝石转换出的速度无法继续强化，也直接出售。

用途型规则还会按品质、强化等级和六星副属性浮动范围反推“有效强化次数”。成品英雄/传说符文通常要求至少 3 次强化落在该用途的相关属性上，允许集中在两种属性中，但不会再把“四次强化中两次歪到无关属性”的符文仅凭属性种类和总效率保留。磨炼不计入强化次数；宝石替换掉的旧强化也不计作当前用途的有效强化。通用高效率、单条极品和高速稀缺规则保持独立，避免重复门槛。

推荐使用顺序：

1. 在 Maa 中确认 ADB 地址为 `127.0.0.1:5559`，分辨率为 `1280x720` 横屏，并让游戏停在庭院默认视野。
2. 运行“启动/重启符文筛选网页”，在网页中导入账号 JSON、预览并保存规则。
3. 先运行“预览仓库筛选结果”。该任务固定为 `dry_run=true`，不会强化或出售。
4. 确认预览结果后，单独选择“仓库符文自动出售”。该任务固定为 `dry_run=false, upgrade=true`，才会执行分阶段强化和出售。

Web 服务启动或重启后会在 Maa/终端的启动任务日志中明确打印 `http://127.0.0.1:端口/` 访问地址，不会自动打开浏览器；如果默认端口被占用并切换到备用端口，提示中的地址会同步显示实际端口。

不通过 Maa 时，在项目根目录运行 `python agent/web_launcher.py --restart` 即可。请统一使用这个启动器，不要直接运行 `agent/web_server.py`；启动器会定位现有实例、等待重启完成，并在权限不足时自动选择备用端口。

开发目录首次运行还必须存在 `assets/resource/model/ocr/det.onnx`、`rec.onnx` 和 `keys.txt`。新增或替换 OCR 模型后需要断开并重新连接 Maa，使资源重新加载。

识别失败、已装备、已锁定或出售确认无法识别时会跳过或停止，不会按兜底策略出售。效率计算兼容公开 SWEX Rune Card 插件，分别显示 `Current`、`Max`、`Hero Grinded` 和 `Legend Grinded`；现有规则中的 `maxWithGrind` 对应 `Legend Grinded`。

符文扫描在每次界面识别前显式请求并等待新截图，不使用 `DirectHit` 节点留下的旧截图缓存；截图失败或为空时停止任务，避免误判符文未打开、确认框已关闭等状态。点击、翻页及强化/出售确认仍保留原有随机偏移、等待和状态验证。

账号 JSON 导入兼容 SWEX/SWKit 常见结构：读取顶层 `runes` 和魔灵 `unit_list[].runes`，解析 `rank/class/set_id/slot_no/pri_eff/prefix_eff/sec_eff/upgrade_curr`，并识别已装备、锁定、远古和品质。`set_id=13` 为暴走，不能把 `extra` 当作品质字段。

账号预览还会统计副属性未精炼速度阶梯，累计显示 30+、25+、20+ 的全部数量、关键套装数量、散件候选数量和逐套装明细；磨炼增加的速度不会计入该统计。

关键套装的六星英雄以上符文会额外保护未精炼速度 20+ 的胚子；其他套装仍使用任意套装速度 23+、高效率或对应用途规则，避免把所有 20 速散件全部留下。

六星传说迅速、暴走、意志符文只有在先天属性达到高值时才作为可洗炼胚子保留：先天暴击率至少 5、先天暴击伤害至少 6、先天效果命中至少 7。普通副属性不参与该规则；低于这些阈值、无先天属性或先天速度/体防攻等其他类型不会命中。该保护不适用于二号位非速度主属性，也不适用于四/六号位体力、攻击力、防御力固定值主属性。

当前账号预设采用逐步筛选：第一轮将所有用途规则的 `maxWithGrind` 门槛统一降到 `90`，只把它作为宽松安全底线；主要依靠用途属性组合和至少 3 次有效强化判断方向是否正确。副属性通常以 `10` 左右为有效起点、速度 `20` 为稀缺高速线；后续应先通过网页预览各用途数量，再按缺口分别提高阈值，避免一次筛得过严。

默认规则还覆盖特殊魔灵：风奥类要求高速并在输出/肉控属性中至少满足两项；风天使保留高速攻击暴击，水希里保留高速攻击爆伤；风马保留高速暴击体力；炸弹流要求速度和命中，**不要求暴击率**；神兽僧/风大王保留体力爆伤且**不把暴击率作为门槛**。这些规则只会扩大保留范围，不会改变已装备、已锁定和识别失败的保护逻辑。

首次使用前请确保 OCR 资源已配置到 `assets/resource/model/ocr/`（发布包会自动带上），并先运行预览任务确认规则命中结果；自动出售任务不会处理已装备符文。

## 运行环境

- Android 模拟器或设备，游戏画面为 `1280x720` 横屏。
- ADB 可执行文件已加入 `PATH`。
- MaaFramework 通用 UI 或 MaaDebugger。

当前开发设备为 MuMu 模拟器，ADB 地址：

```text
127.0.0.1:5559
```

连接检查：

```powershell
adb connect 127.0.0.1:5559
adb devices -l
```

在通用 UI 中选择 `MuMu 模拟器` 控制器和 `国服中文` 资源，然后执行：

- `启动游戏`：冷启动并等待进入庭院。
- `打开连续战斗`：从庭院默认视野打开连续战斗界面。
- `配置连续战斗`：打开连续战斗建筑，并按界面配置选择目标。

`配置连续战斗` 支持以下目标：

- 卡伊洛斯地下城：巨人、龙、死亡、精灵、钢铁、审判。
- 卡伊洛斯层数：地下1至10层、深渊普通、深渊困难。
- 次元洞口区域：卡勒赞、艾鲁尼亚、拉莫、卡尔德隆、塞克里翁、焰焚炼狱。
- 次元洞口难度：阶段1至5。

次元洞口会选择目标区域左侧列表中的第一个常规地下城，不选择二次觉醒支线。未通关或锁定的层数无法进入队伍配置页，任务会失败，不会误报选择成功。

执行 `打开连续战斗` 或 `配置连续战斗` 前，请确保连续战斗建筑位于进入庭院后的默认可见范围内。
